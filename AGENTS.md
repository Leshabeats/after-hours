# After Hours

TanStack Start app. Product copy is Russian; mission kinds are After Hours track names.

- Catalog shows projects, issues live at `/r/$owner/$repo`. Worlds are Web, Stars, Linux, AI, GameDev (`cat=games`), and Data. A language chip adds that language's ecosystem and its libraries, and keeps the world: direction projects whose GitHub language matches stay in their own section. Inside a repo, issues and pull requests are separate recent slices, and an issue already fixed by a merged PR is omitted when that lookup succeeds.
- GameDev discovery is public-only: require explicit public GitHub metadata, reject private/unknown visibility, and hide legacy unmarked or subsequently revoked cards on reads. Private responses must never replace stored public descriptions or generate metrics.
- GameDev discovery reads the last fully published PostgreSQL snapshot; never collect GitHub data or run DDL in the discovery read path. Keep GitHub creation, first discovery, and measured growth distinct. Collector writes require a fenced lease; partial runs keep their checkpoint and cannot replace the published snapshot. No weekly growth without observed history plus activity evidence. Identity validation must preserve still-fresh count measurements and their baseline; search/rotating refresh sample new counts. Before publishing, validate every ranked winner by stable GitHub ID, including replacements after expiry or exclusion. `docs/examples/catalog-discovery.yml` is an inactive template: moving/enabling it, new credentials, production migration and deployment require their own authorization. Tests use fixtures/local isolated PostgreSQL only.
- Journal: anonymous = `localStorage`. Signed-in GitHub user = Neon PostgreSQL via pooled `DATABASE_URL`, scoped by GitHub user id. Never trust a client-sent user id. OAuth is GitHub only (`read:user`), session cookie, no Grok auth chrome. On first GitHub login, if the server journal is empty and the device journal has entries, `importDeviceJournal` copies them once (session user id only). If both journals have data, keep the server copy — do not auto-merge. `/log` shows night stats from journal entries via `summarizeJournal` — counts only. Signed-in `/log` also shows token spend from `usage_events` (local harness `POST /api/usage` / `reportUsage`; session user id only). After Hours does not run the agent, proxy model calls, or store GitHub tokens. Anonymous `/log` hides token totals.
- Frontend and backend deploy together to Vercel with `npm run build:vercel` (Nitro vercel preset). `npm run build` retains the node-server preset for production smoke. PostgreSQL persists outside the deployment; no runtime SQLite or persistent application disk. Codex/connector remain desktop-only.
- Development uses a separate Neon development branch, production its own branch. Preview uses development with OAuth credentials unset and `VERCEL_ENV=preview` disabling OAuth. Preserve the local OAuth callback `http://127.0.0.1:5173/api/auth/callback`; production needs a separate GitHub OAuth App for its actual hostname.
- Node 22 / npm 11. Dev/start/migrations load `.env.local` explicitly; tests never load it. Runtime `DATABASE_URL` is pooled; `DATABASE_URL_UNPOOLED` is direct for `npm run db:migrate`. Versioned SQL lives in `migrations/`; never execute DDL in HTTP paths. This starts with an empty database; no historical SQLite import.
- Repositories (including memory tests) are async. Journal mutations/imports lock by user; research ingest/publication lock by thread, including first writes. Watch observation/dedup transactions never include network requests; rate-limit pause is shared in PostgreSQL. Preserve token hashing, publication/privacy, case-insensitive lookups, and replay accounting.
- CI uses ephemeral PostgreSQL 17. Database tests and `npm run test:production` require isolated local `TEST_DATABASE_URL` ending in `_test`, create/drop random schemas, and never use working DB URLs. Smoke disables external fetch and does not validate real OAuth or a model run. `AUTH_SECRET` is mandatory in production; filesystem fallback is development-only.
- Backend is TanStack Start server functions + `/api/auth/*` in the same Node process. Not a separate Nest/Fastify app.
- "Взять эту ночь" and "Разобрать" open `codex://threads/new` in the visitor's browser. The server does not run Codex and does not use a site model key.
- Do not reintroduce Grok App Builder chrome (`.grok/`, `public/__grok/`, PWA injector, preview host bridge, auth/db scaffolding).
