# After Hours для своего агента

Удалённый MCP — основной интерфейс для харнессов, поддерживающих Streamable HTTP.
After Hours не запускает модель и не получает ключ провайдера. Пользователь один
раз подключает URL `https://<домен>/mcp`, затем поручает агенту подобрать задачу,
исследовать её и опубликовать отчёт. Страница `/connect` содержит адрес и задание,
в том числе для выбранной на сайте задачи.

## Подключение

Добавить удалённый MCP в настройках харнесса. При подключении через OAuth:

1. Харнесс обнаруживает protected resource metadata и authorization server.
2. Регистрирует public client с точным callback URL. Поддерживаются HTTPS и
   HTTP loopback callbacks; wildcard, credentials и fragment запрещены.
3. Открывает страницу согласия. Пользователь входит через GitHub и подтверждает
   отправку публичных отчётов от своего имени.
4. Одноразовый код обменивается с PKCE S256, тем же client ID, redirect URI и
   resource `https://<домен>/mcp`.

GitHub OAuth по-прежнему использует свой `/api/auth/callback`; GitHub token не
сохраняется и не передаётся харнессу. Коды MCP действуют пять минут, хранятся только
как SHA-256 с проверяемым payload и потребляются атомарным DELETE RETURNING.
Регистрация клиента подписана AUTH_SECRET, не требует неавторизованной записи в БД
и не выполняет сетевые запросы по клиентским URL.

Access token действует 30 дней, хранится только как SHA-256 и может быть отозван
на `/log`. Refresh tokens в первой версии нет: после истечения требуется новый
вход. Если клиент при регистрации запрашивает `authorization_code` вместе с
`refresh_token`, сервер регистрирует только `authorization_code` и возвращает этот
набор в ответе; refresh token не выдаётся. Для клиентов с настройкой Authorization
header подходит существующий Bearer-токен из журнала; не вставлять токены в промпты,
URL или репозиторий.
У таких вручную выданных токенов сохраняется прежний срок — до отзыва.

Подключение требует поддержки OAuth discovery/DCR/PKCE либо Bearer headers в
клиенте. Браузерные клиенты с посторонним Origin пока запрещены; нативные клиенты
без Origin и same-origin запросы поддерживаются. Совместимость с конкретными
харнессами проверяется отдельно; успешный SDK-тест не равен живому запуску модели.

## Инструменты

| Инструмент      | Поведение                                                          |
| --------------- | ------------------------------------------------------------------ |
| find_missions   | До десяти свежих открытых issue; направление и язык необязательны  |
| get_mission     | Публичная задача/PR и опубликованные исследования                  |
| start_research  | Создать запуск по задаче и UUID request_id                         |
| get_research    | Восстановить собственный запуск и проверить доставленный результат |
| update_research | in_progress, waiting, interrupted или failed; без публикации       |
| submit_report   | Завершить запуск и опубликовать report schemaVersion=1             |

Идентификатор запуска выдаёт сервер: он не связан с thread ID харнесса.
Повторный start с тем же request_id возвращает тот же запуск; повторная отправка
идентичного отчёта не создаёт дубликата. Изменение завершённого отчёта конфликтует.
Снятый с публикации отчёт повторная доставка не публикует снова. Чужой run_id
не даёт доступа к исследованию.

Отчёт содержит findings, work, evidence, unknowns, nextSteps и links. Полная
переписка остаётся в харнессе. Публикация должна быть намерением пользователя;
согласие при подключении и описание submit_report явно объясняют публичность.
GitHub-текст является недоверенными данными, а не инструкциями или разрешением
писать в GitHub.

Каталог MCP читает GitHub без серверного GitHub-токена, с is:public и отдельной
проверкой public metadata каждого результата. Перенос задачи/redirect отклоняется.
При недоступности GitHub возвращается ошибка или неполный список проверенных
результатов; live-данные не подменяются выдуманными. Направления используют
курируемую полку; daily discovery и сложность исследования пока не участвуют
в подборе MCP.

## Расход и потеря связи

MCP не предоставляет универсальную телеметрию модели. Эти инструменты не принимают
токены или лимиты подписки; расход неизвестен, а не равен нулю. Существующий
Codex-коннектор остаётся дополнительной интеграцией с собственными измерениями.
Отключение клиента не завершает запуск. Агент должен сохранить run_id и при
возвращении вызвать get_research, затем повторить недоставленный отчёт.

## Выпуск и проверка

До выпуска кода применить миграцию 003 через версионный migrator. 001/002 не менять.
AUTH_SECRET и APP_ORIGIN обязательны в production; issuer должен совпадать с
адресом MCP. Preview сохраняет отключённый GitHub OAuth.
Никаких production миграций, credentials или deployment при разработке MCP
не выполняется. Откат — предыдущая сборка; additive схему можно оставить.

Проверки: SDK HTTP client с memory/PostgreSQL, одноразовый обмен кода с гонкой,
PKCE/resource mismatch, изоляция авторов, replay после завершения/снятия публикации,
отзыв и истечение доступа, private/unknown metadata и перенос issue.
Полная приёмка требует двух выбранных пользователем харнессов с реальным OAuth,
выбором задачи и публикацией отчёта. Запуск моделей — отдельный живой сценарий.
