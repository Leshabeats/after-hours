# Локальный коннектор исследования

Коннектор для [#9](https://github.com/Leshabeats/after-hours/issues/9). Это отдельный процесс на компьютере исследователя. Сайт не запускает Codex и не хранит ключ модели. Кнопки «Взять эту ночь» и «Протокол агента» по-прежнему открывают `codex://threads/new` без коннектора. Автоматическая публикация отчёта привязана к выданному доступу.

## Установка

Нужны Node.js 22, репозиторий After Hours и `codex-cli` **0.159.x**. Спайк [#7](codex-app-server.md) проверен на `0.159.0` и бандле Desktop `0.159.2`. Другая версия не блокирует запуск: скрипт пишет предупреждение и продолжает. Живой прогон остаётся задачей [#12](https://github.com/Leshabeats/after-hours/issues/12).

```bash
node --experimental-strip-types scripts/research-connector.mjs --help
```

## Подключение

1. Войти на сайт через GitHub.
2. На `/log` нажать «Выдать доступ». Токен показывается один раз, начинается с `ahc_`.
3. Сохранить его в файл, который не попадает в git:

```bash
umask 077
cat > ~/.after-hours-token
chmod 600 ~/.after-hours-token
```

4. Запустить исследование публичной задачи:

```bash
node --experimental-strip-types scripts/research-connector.mjs \
  --origin http://127.0.0.1:5173 \
  --token-file ~/.after-hours-token \
  --mission vitejs/vite#123 \
  --queue ~/.after-hours/research-queue.json
```

`--origin` — адрес своего сайта, `http` или `https`. `--mission` — `owner/repo#номер`. Коннектор читает задачу через публичный `api.github.com` без токена GitHub. Если задача не прочиталась, Codex не стартует.

Тред эфемерный, каталог пустой временный, sandbox `read-only`, approval `on-request`. Запросы на команду, правку файла и патч отклоняются. Исследование не публикует комментарий и не открывает pull request.

На `/log` у доступа написано «Ещё не обращался», пока не было успешной проверки токена. После неё строка меняется на «Последнее обращение». Очередь на диске сайт не видит.

## Очередь

На диске лежит последний снимок каждого `threadId`, а не список дельт. Повтор того же снимка сервер принимает как повтор и не создаёт вторую строку расхода. `400` и `409` остаются в `blocked` и в этом файле больше не отправляются. Сеть и `401` оставляют снимок в очереди и останавливают проход.

Пока сеть недоступна, снимок уже записан. После возвращения:

```bash
node --experimental-strip-types scripts/research-connector.mjs \
  --origin http://127.0.0.1:5173 \
  --token-file ~/.after-hours-token \
  --queue ~/.after-hours/research-queue.json \
  --flush-only
```

`--flush-only` не запускает Codex. Один файл очереди обслуживает один процесс. Ctrl-C останавливает локальный Codex, помечает ход прерванным и досылает уже известный расход.

Публикуется только ход со статусом `completed` и отчётом schema v1. Ожидание человека и прерывание записывают известный расход и не получают `publishedAt`. Если ответ завершился без такого JSON, на сервер уходит `failed`, без отчёта. В расход попадают поля `last` из `thread/tokenUsage/updated`. Числа из текста ответа и расход другого `threadId` не суммируются.

## Отключение

На `/log` нажать «Отозвать». Отозванный токен получает тот же `401`, что и неизвестный. Локальный файл токена и очередь скрипт не удаляет: файл токена можно стереть, очередь дослать нечем, пока не выдан новый доступ. Новый доступ — новый токен, старый остаётся отозванным.
