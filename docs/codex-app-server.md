# Локальный Codex: решение по интеграции

Спайк для [#7](https://github.com/Leshabeats/after-hours/issues/7). Проверено 2026-10-03 на `codex-cli 0.159.0` (`~/.local/bin/codex`) и схеме `codex app-server generate-json-schema` без `--experimental`. Бандл Desktop — `codex-cli 0.159.2`. Команда `app-server` в `--help` помечена experimental. Транспорт WebSocket в документации experimental; этот спайк ходил только в `stdio://`.

## Решение

Автоматическая связь задачи и чата делается локальным коннектором. Он запускает `codex app-server --listen stdio://`, сам вызывает `thread/start` или `thread/resume` и сохраняет возвращённый `thread.id` рядом с `missionId` (`owner/repo#number`). Сайт по-прежнему не запускает агента и не хранит ключ модели.

Текущий `codex://threads/new?prompt=` остаётся ручным действием в браузере. В ссылке нет id чата, приложение его не возвращает, а в бинарнике рядом с `codex://threads/new?` нет других имён параметров. У треда нет поля внешнего id: `thread/metadata/update` меняет только git-метаданные, `thread/name/set` задаёт заголовок.

Отдельный процесс app-server видит уже записанные чаты Desktop через `thread/list`. У них `source: "vscode"`, `originator: "Codex Desktop"`, id — UUID, до `thread/resume` статус `notLoaded`. Совпадение такого чата с задачей по тексту промпта — эвристика, не ключ связи.

## Живой прогон

3 октября 2026, `codex-cli 0.159.0`, модель `gpt-6-astra`, провайдер `openai`. Каталог хода — пустой `/tmp/ah-empty-cwd`. Тред эфемерный, sandbox `read-only`, approval `on-request`. В `turn/start` передан `effort: "low"`. Поле `reasoningEffort` у треда осталось `max` из локального конфига. `reasoningOutputTokens` был 0.

Клиент запомнил связь сам. `thread/start` вернул `thread.id`, и оба события расхода пришли с этим id и с id своего хода. `missionId` сервер не хранит: строка `Leshabeats/after-hours#7` была только в тексте. `source` такого треда — `vscode`, как у Desktop. `originator` равен имени из `initialize.clientInfo` (`ah_wait_probe` на втором треде), у Desktop в списке было `Codex Desktop`.

Первый ход, просьба ответить `PONG`:

|              | input | cached | output | reasoning | total |
| ------------ | ----- | ------ | ------ | --------- | ----- |
| last = total | 23775 | 7168   | 6      | 0         | 23781 |

Второй ход, `QONG`, в том же треде:

|       | input | cached | output | reasoning | total |
| ----- | ----- | ------ | ------ | --------- | ----- |
| last  | 30175 | 23552  | 6      | 0         | 30181 |
| total | 53950 | 30720  | 12     | 0         | 53962 |

`total` второго события равен сумме `last` первого и `last` второго по input, cached, output и total. Короткий ответ стоит около 24–30 тысяч input: это размер служебного промпта, не длина «PONG». На ходу с просьбой выполнить `echo hi` пришли два события одного `turnId`: `last.totalTokens` вырос с 23803 до 23871. Рост на 68 похож на дописанный хвост снимка, но поля первого события с `total` не сравнивались. Рабочее правило, не доказанный контракт: в учёт кандидата берётся последний `last` хода, а уведомления подряд не складываются.

Прерывание сразу после `turn/start` не прислало `thread/tokenUsage/updated`. Расход этого хода неизвестен, это не ноль.

Окно `primary` до двух первых ходов и после всего прогона имело одну и ту же целую долю при длительности 10080 минут. За эти токены процент не сдвинулся. `secondary` остался `null`.

Эфемерные треды не попали на первую страницу `thread/list`: там по-прежнему недавние чаты Desktop.

## Прототип

```bash
node scripts/codex-app-server-probe.mjs
```

Скрипт делает `initialize`, `thread/list` и `account/rateLimits/read`. Список читает только state DB (`useStateDbOnly`) и все провайдеры (`modelProviders: []`). Обычные и архивные треды запрашиваются отдельно: без `archived: true` сервер архив не отдаёт. Счётчик помечен `scope: interactive`. Если в сводке есть `exec`, `appServer` или `unknown`, метка называет только их: `interactive+exec`. Сначала запрос без `sourceKinds`: сервер сам берёт интерактивный список, включая пользовательские источники вроде Atlas и ChatGPT. Отдельно добавляются `exec`, `appServer` и `unknown`. Sub-agent треды не входят, повтор одного id не считается дважды. Ошибка обычного списка не отменяет чтение лимита, в том числе таймаут или обрыв запроса. Ошибка чтения лимита оставляет уже посчитанные треды, в том числе если связь оборвалась после успешного списка. Обрыв первого списка тоже остаётся ошибкой списка, а не падением пробы. Ответ списка может быть длиннее строки stderr. Ошибка дополнительного списка пишется только в `extraSourceError`, обычного архива — только в `archivedError`, архивного дополнительного — только в `archivedExtraError`. Уже прочитанные треды других срезов не выбрасываются. `turn/start` и `thread/start` он отклоняет. В вывод не попадают id чатов, в том числе UUID рядом с `_`, тексты, пути и id аккаунта. Комбинируемый знак входит в имя, в локальную часть почты и в домен. Имя без расширения с пробелом (`sessions\Jane Doe`, `O'Brien\secrets`, `Private Project/secrets/key.txt`, `Private (old)/secret/key.txt`) вычищается. `@` в пути URL не съедает хост, в том числе `localhost` и сегмент с точкой. `first.last/team@example.com` вычищается целиком. Адрес без точки, `alice@localhost`, `alice@mailserver1`, `alice@x`, `alice@3com` и `alice@1`, тоже, включая точку в конце фразы. Однобуквенный хвост, `alice@corp.x`, и буква вне BMP, `alice@𐐀`, тоже. Хвост с дефисом, `alice@corp.mail-server`, тоже. Дефис в конце метки остаётся. Не-ASCII в локальной части (`user١@example.com`) тоже вычищается. Цифра вне ASCII в домене, `alice@مثال١.إختبار`, вычищается целиком. Цифра, прилипшая к уже готовому домену, `alice@ex.com١`, не прячет адрес: остаётся `[redacted]١`. Адрес в скобках, `alice@[private.example]` и `alice@[private\]example]`, вычищается целиком. Встречный запрос сервера не считается ответом пробы. Слишком длинная ошибка RPC заменяется на `[redacted]`. Комментарий перед `@` (`user(comment)@example.com`, в том числе с `@` внутри комментария и с переводом строки перед `@`) входит в адрес только если домен настоящий. Иначе адрес внутри комментария или кавычек всё равно вычищается, а голое `слово @` внутри них тоже. Комментарий сразу после `@` (`alice@(private)example.com`) входит в адрес. Пробел после `@` делает доменом только имя с точкой или адрес в скобках (`alice@ example.com`), не следующее слово (`alice@ because`). Адрес в кавычках или в скобках, которые не стоят перед разделителем, тоже вычищается. Более ранний URL не отрезает `/` у следующего адреса. Слово `because` перед следующим путём остаётся, а строчное `files` перед `(x86)` или `files\key` входит в путь. Пароль с двоеточием в `user:pass@host` не обрезает адрес до имени. Метка originator и имя custom-источника с путём, почтой или id схлопываются в `[redacted]`. Обычное имя клиента и `custom:atlas` остаются. То же вычищается из текста ошибок до обрезки stderr, даже если сырой путь длиннее буфера, включая UNC, путь от одного обратного слэша (`\Users\...`, `\Documents and Settings\...` и файл `\secret.txt`, относительный путь `PrivateProject\secrets\key.txt` и `Private=Customer\secrets\key.txt` и путь без расширения `PrivateProject\secrets` и `PrivateProject/secrets` с первого компонента, в том числе перед `later.`. Строчные слова в начале пути, `my private files/secrets/key.txt`, вычищаются целиком. Фраза перед именем остаётся (`failed to read src/private/key.txt`, `Failed=src\private\key.txt`, `file.txt=note\other\path.txt`). Скобки с пробелом, `(os error 3)`, перед путём остаются в тексте. Буква вне BMP в пути или в домене (`alice@𐐀.com`, `𐐀Project/secrets`) тоже вычищается, включая несколько слов (`sessions\Jane Mary Doe.jsonl`, `my documents\secrets\key.txt`). Путь с любым знаком в первом имени, `project@client/secrets/key.txt`, `R&D/client/secrets/key.txt` и `Private=Customer/secrets/key.txt`, вычищается целиком. Слово ошибки перед уже целым путём остаётся, в том числе через запятую, двоеточие или перевод строки (`Cannot open sessions\...`, `Error,src/private/key.txt`, `Error:src/private/key.txt`, `See\nsrc/private/key.txt`). Имя из любого числа слов перед каталогом входит в путь (`Very Private Customer Project\...`, `Jane Doe Documents\...`). Слова ошибки `Missing`, `Error`, `See`, `The`, `From` остаются. Путь с начала строки забирает первое слово (`my documents\...`). Корень без расширения (`\secret`, `\Private Folder`, `\My documents`, `\Секрет`) забирает следующее слово с заглавной, `and` перед ним и одно строчное `documents` или `документы`. Запятая, двоеточие и фраза после корня остаются. Группа без пробела, как `(x86)`, остаётся частью каталога, в том числе после слова ошибки (`Missing (old)/secret/key.txt`). Группа с пробелом, как `(os error 3)`, остаётся в тексте. Цепочка незакрытых скобок читается один раз. Относительный путь `src/private/key.txt` вычищается с первого компонента, в том числе кириллического (`Проект/секреты/key.txt`) и с апострофом (`O'Brien/secrets/key.txt`). Один слэш перед обратным не забирает фразу ошибки (`src/file.txt\more because`). Один слэш без второй части пути остаётся (`read/write`, `node/v22.0.0`)), `file://`, путь сразу после двоеточия метки (`cwd:/secret`), апостроф в имени, папку без расширения и все слова пути до закрывающей кавычки или до компонента с точкой. Удалённый URI с непустым хостом копируется до пробела, кавычки или двоеточия, за которым начинается локальный путь, в том числе `~/`, `~\` и `~имя/`. Порт в хосте остаётся. Userinfo, query и fragment из этого URI убираются. Почта вычищается и из текста ошибок, включая нелатинские буквы, апостроф в локальной части и punycode-домен. Точка или другой хвост после адреса остаётся. Адрес с локальной частью в кавычках, в том числе с `@` внутри кавычек (`"a@b"@example.com`), адрес с остальными символами dot-atom (`alice!private@example.com`) и адрес с IP в скобках тоже вычищаются. Следующий адрес не становится доменом предыдущего. User-Agent и ошибка разбора аргументов проходят ту же очистку. Слэш после буквы или цифры, как в `codex_cli_rs/0.159.0`, остаётся. Абсолютный путь, `C:secret.txt`, путь на текущем каталоге диска без расширения и с пробелом (`C:secret`, `D:PrivateFolder`, `C:Users\Alice`, `C:My Secret.txt`, `C:Users\Jane Doe`, `C:Private Folder`, `C:Program Files (x86)\secret.txt`) и `cwd:/...` вычищаются. Точка в конце фразы (`because.`), `e.g.` и `v2.0` остаются. Строка JSON `null` в stdout пропускается. Удалённый URI останавливается и перед `:C:secret.txt`. На Windows `codex.cmd` запускается через `cmd.exe`, путь со скобками квотируется, путь с `%` передаётся переменной окружения, командная строка не квотируется повторно, stdin закрывается, а дерево процессов останавливается через `taskkill /t /f`. Если это не удалось, процесс останавливается напрямую. Если SIGTERM процесс не завершил, через секунду приходит SIGKILL, и этот таймер держит процесс, даже если обёртка уже вышла. Ctrl-C в эту секунду тоже бьёт в группу. На POSIX процесс стартует своей группой, и оба сигнала идут в группу. SIGINT и SIGTERM скрипта тоже останавливают эту группу до выхода. На Windows скрипт дожидается `taskkill` и только потом выходит. Отказ прямого kill не выбрасывает готовую сводку: следом идёт SIGKILL. Пустой хост (`http:///...`) и `file://` вычищаются. В метке originator и custom-источника адрес с путём после хоста схлопывается в `[redacted]`, адрес только с хостом остаётся. Отсутствующий originator считается в `missingOriginators`. Строка `null` остаётся обычной меткой. Недописанная строка stderr длиннее лимита выбрасывается целиком, вместе с хвостом до перевода строки. Закрытый stdin завершает запрос сразу и останавливает живой процесс. Ошибка stdout тоже отклоняет ожидающие запросы и останавливает процесс. Процент лимита печатается только локально. Сводка лимита хранит `spendControlReached`, остаток индивидуального лимита, флаги `credits.hasCredits` / `credits.unlimited` без баланса и `resetCreditsAvailable` из `rateLimitResetCredits.availableCount`. Id и тексты кредитов сброса не копируются. Запрос лимита передаёт `excludeResetCreditDetails: true`. Если поля нет, это `null`.

## Что это даёт [#8](https://github.com/Leshabeats/after-hours/issues/8)

Сервер может хранить запуск как пару `threadId` и `turnId`. Для двух разных ходов `total` равен сумме их `last`, поэтому накопительный `total` с последним `last` не складывают. Внутри одного хода рабочее правило — писать последний `last` (`inputTokens` и `outputTokens`), а не сумму уведомлений. Это гипотеза, пока два события одного `turnId` не сверены по полям. `cachedInputTokens` внутрь input уже входит, второй раз его не прибавлять. Повтор того же `turnId` не создаёт вторую строку. Если события расхода не было, значение неизвестно, не ноль. `reasoningOutputTokens` хранить отдельно, пока не появится ход с ненулевым reasoning.

Живой флаг ожидания человека этот прогон не поймал. Обработку `waitingOnApproval` и `waitingOnUserInput` нужно оставить в контракте, но текущие имена подтверждены схемой, не этим запуском. Один `completed` по-прежнему не означает готовый отчёт исследования: здесь завершением был односложный ответ.
