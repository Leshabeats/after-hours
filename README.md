# After Hours

Ночная доска миссий по живому опенсорсу. Жги токены на issue и PR в репозиториях от 1000 звёзд: сначала топ репозиториев, потом их задачи. Веб на виду сразу; дальше направление (Stars, Go, Linux, …) и язык.

Ночь может выбрать цель сама, можно взять список, можно вставить свой GitHub URL. Журнал без входа живёт в браузере; после GitHub OAuth — на сервере, в SQLite. Если в аккаунте пусто, ночи с устройства заливаются один раз; если журнал на сервере уже есть, он не смешивается с локальным.

## Запуск

Нужен Node 22+.

```bash
cp .env.example .env
npm install
npm run dev
```

Открой [http://127.0.0.1:5173](http://127.0.0.1:5173).

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер на `:5173` |
| `npm run build` | production-сборка |
| `npm run preview` | собранное приложение на `:4173` |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | тесты каталога, журнала, исследований и коннектора |
| `npm run smoke` | после сборки: preview на временном `DATA_DIR`, старая база переживает перезапуск |

## Переменные

Ни одна не обязательна, кроме GitHub OAuth если нужен вход.

- `GITHUB_TOKEN` — живой каталог с GitHub. Без токена приложение быстро упрётся в rate limit и покажет зашитый seed.
- «Взять эту ночь» и «Разобрать» открывают Codex на компьютере того, кто нажал. Сервер агента не запускает.
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` — вход через GitHub. OAuth App: Homepage `http://127.0.0.1:5173`, callback `http://127.0.0.1:5173/api/auth/callback`.
- `APP_ORIGIN` — публичный origin для redirect URI.
- `AUTH_SECRET` — подпись сессии, от 32 символов. Локально файл `.auth-secret` создаётся сам в каталоге данных. В production без этой переменной сервер не стартует сессию.
- `DATA_DIR` — каталог SQLite и локального секрета. Пусто значит `data/` от текущего каталога процесса. Абсолютный путь нужен, когда процесс запускают не из корня приложения.

Бэкенд — это не отдельный сервис. Каталог, OAuth, журнал и исследования крутятся в том же Node-процессе TanStack Start. Файл базы — `after-hours.sqlite` в каталоге данных.

Старый файл открывается как есть. Недостающие таблицы исследований добавляются при первом чтении, строки журнала и `usage_events` остаются. Повторный запуск вторую копию не создаёт. Откат этого выпуска — вернуть предыдущий код. Без `DATA_DIR` путь снова `data/`. Новые таблицы можно оставить или удалить через `DROP TABLE`. Журнал и расход откат не чистит. Снятие отчёта с публикации — кнопка на карточке, не миграция.

Локальные `npm test`, typecheck, lint, build и `npm run smoke` не равны зелёному CI и не равны мержу. Деплой на хост — отдельное действие: этот репозиторий его не выполняет. Smoke и живой Codex остаются на машине исследователя, в CI нет сессии OAuth и подписки Codex.

## Расход токенов

After Hours не запускает агента и не проксирует вызовы модели. Локальный харнес после GitHub-входа пишет расход в SQLite (`usage_events`, ключ — id пользователя из сессии, не из тела запроса). GitHub-токены не храним.

Cookie `ah_session` копируется из браузера после OAuth.

```bash
curl -sS -X POST http://127.0.0.1:5173/api/usage \
  -H 'Content-Type: application/json' \
  -H "Cookie: ah_session=$AH_SESSION" \
  -d '{"harness":"codex","model":"grok-4","inputTokens":1200,"outputTokens":400,"missionId":"vitejs/vite#19909"}'
```

На `/log` у вошедших: токены за 7 дней, всего, имя последнего харнеса. Без входа блок прячется с просьбой войти.

## Исследования

Публичный отчёт появляется на странице задачи и в профиле `/u/<login>`, когда локальный коннектор довёл запуск до schema v1. Расход на карточке — сумма известных ходов этого запуска. Остаток лимита подписки виден только владельцу на `/log`. Снять отчёт может автор: обе публичные страницы его прячут, скрытая карточка остаётся у него.

Блок «На GitHub» читает задачу и PR из ссылок отчёта, когда страницу открывают. Тела комментариев не хранятся. «Исправлено автором» требует явной ссылки, того же автора, влитого PR и закрывающей связи GraphQL. Для GraphQL нужен `GITHUB_TOKEN`. Без него публичный PR всё равно читается через REST.

Подключение коннектора, очередь и повторная отправка после обрыва сети: [docs/research-connector.md](docs/research-connector.md). Сайт Codex не запускает. Кнопки «Взять эту ночь» и «Разобрать» по-прежнему открывают приложение на компьютере гостя.

## Что это не делает

Нет облачного агента. After Hours не вызывает модель за харнес и не принимает `userId` от клиента. Без OAuth журнал остаётся в `localStorage`, расход токенов не пишется.

Прототип собран в Grok App Builder и вычищен в обычный TanStack Start репозиторий.
